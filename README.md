# Cone-Projected Greedy for parametrized variational inequalities

Implementation of the core contribution of:

> A. Benaceur, A. Ern, V. Ehrlacher.
> *A reduced basis method for parametrized variational inequalities applied to
> contact mechanics.* Preprint, HAL [`hal-02081485v2`](https://hal.science/hal-02081485v2).

Every non-trivial line of source cites the paper section, equation, or algorithm
line it comes from. Choices the paper does not specify are marked `[UNSPECIFIED]`
at the point of use and collected in [REPRODUCTION_NOTES.md](REPRODUCTION_NOTES.md).

**Read [REPRODUCTION_NOTES.md](REPRODUCTION_NOTES.md) before using this.** It states
what is and is not implemented, and records two extraction hazards that affect how
far the transcribed equations can be trusted.

## The problem

For a parameter `µ`, solve a constrained minimization (Eq. 1)

```
u(µ) = argmin_v  ½ a(µ; v,v) − f(µ; v)     s.t.   k(µ,u;u) ≤ g(µ,u)  on Γ_c
```

recast via Lagrange multipliers as a saddle-point problem (Eq. 5–6). Discretized,
this is Eq. (9): find `(u(µ), λ(µ)) ∈ R^N × R^R_+`. The multipliers `λ` are the
contact pressures and are **non-negative by construction**.

Reduced-basis model order reduction needs a small basis for the multiplier
manifold. The obstacle: **POD is not usable for the dual**, because POD modes have
mixed signs and would destroy `λ ≥ 0` (§5).

## The contribution

**Algorithm 2, Cone-Projected Greedy.** Build a *cone* — non-negative combinations
only — generated by selected multiplier snapshots. Greedily add the snapshot
currently worst-represented by the cone built so far (Eq. 57), stopping on a
tolerance (Eq. 58):

```
K₀⁺ = {0}
while  r_n > ε_du:
    µ_n ∈ argmax_µ ‖λ(µ) − Π_{K⁺_{n−1}}(λ(µ))‖_Λ      # Eq. (57)
    K_n⁺ = span₊{λ(µ₁), …, λ(µ_n)}
    r_n  = max_µ ‖λ(µ) − Π_{K⁺_{n−1}}(λ(µ))‖_Λ         # Eq. (58)
```

`span₊` restricts coefficients to be non-negative, so every element of the cone —
and hence every reduced multiplier — is automatically non-negative.

The one non-obvious numerical piece is `Π_{K⁺}`, the projection onto a finitely
generated convex cone. It is the solution of `min_{c ≥ 0} ‖λ − Gc‖`, i.e. a
**non-negative least squares** problem, and it is *not* linear in `λ` — there is no
projection matrix to precompute. The paper solves it with `cvxopt`; this code uses
`scipy.optimize.nnls`, which is equivalent for the L² norm.

## Layout

The cone algorithms live in a **shared library**, [`~/rb_vi_shared`](../rb_vi_shared),
together with the sequel implemented in
[`~/stable_model_reduction_vi`](../stable_model_reduction_vi). See that library's
README before touching a citation: because both papers number an "Algorithm 1",
an "Algorithm 2" and an "Eq. (57)" differently, **every citation in shared code
carries a paper tag** — `[BEE20]` for this paper (preprint-v2 numbering),
`[NDEE22]` for the sequel.

```
~/rb_vi_shared/rb_vi_common/
    cone_projection.py   Π_{K⁺} via NNLS; the ‖·‖_Λ norm      [BEE20] §5, Eq. (57)
    cone_greedy.py       Algorithm 2 line by line, plus the   [BEE20] §5;
                         sequel's mCPG and its CPG baseline   [NDEE22] §4
    reduction.py         whitening, POD, supremizers, inf-sup [NDEE22] §2–§3
    pga.py               PGA                                  [NDEE22] Alg. 1

src/nmf_baseline.py        NMF dual basis, the comparison method  [BEE20] §6.4, Eq. (66)–(69)

                           + optional [NDEE22] supremizer/PGA stabilization
src/toy_problem.py         1-D obstacle problem — NOT from the paper
src/contact_dataset.py     Hertz half-plane contact, validated — NOT from the paper
src/make_dataset.py        dataset export

```

`nmf_baseline.py` deliberately stays here: it is `[BEE20]` §6.4 and the sequel
does not use it. The test problems stay here for the same reason — merging them
would blur which paper a given result speaks to.

## Run

```bash
pip install -r requirements.txt
cd src && python3 run_demo.py
```

`numpy` + `scipy` only; a few seconds on CPU. Nothing needs installing for the
shared library — `_shared_path.py` finds it at `../../rb_vi_shared`.

The inf-sup evaluation of the Hertz model is a separate script (a few minutes,
mostly LP/QP certificates):

```bash
cd src && python3 hertz_infsup_probe.py
```

## What the demo shows

- CPG selects a nested cone and the residual `r_n` decreases monotonically.
- The tolerance `ε_du` of Eq. (58) is **absolute**, so it must be read against the
  snapshot scale; the demo sweeps it as a fraction of `max‖λ(µ)‖`.
- Reduced multipliers come out non-negative, which is the property the method exists
  to preserve.
- At matched cardinality, **NMF is somewhat more accurate than CPG on this toy** —
  see REPRODUCTION_NOTES.md, which explains why this is expected and why it is not
  the axis on which §5 argues for CPG.
- The reduced solve is run **with and without** the sequel's inf-sup
  stabilization (supremizer enrichment, its Eq. 17, compressed offline by PGA,
  its Eq. 27–29). Algorithm 1 line 4 as published has none.

## Inf-sup stabilization — added from the sequel

Algorithm 1 line 4 builds `V_N` (POD) and `W_R⁺` (CPG) independently and solves
over the pair with **no inf-sup stabilization**; this paper supplies none. The
sequel is the paper that closes that gap. `rb_online.solve_reduced` therefore
takes an optional `enrichment` — **omitting it reproduces Algorithm 1 line 4 bit
for bit**, so the transcription stays intact and testable.

Read the honest caveat before quoting a number: the toy has `B = I`, a
parameter-*independent* constraint, so PGA's headline benefit (removing an online
construction cost) is vacuous here, and `β^dec = 2.4e-01 > 0` means the pair was
already stable. Enrichment roughly halves the constraint violation but does not
improve the primal error. Details and the table are in
[REPRODUCTION_NOTES.md](REPRODUCTION_NOTES.md).

## Is the Hertz model a better test problem for those experiments?

`src/contact_dataset.py` is a validated Hertz contact model, and the obvious
question is whether it could host the sequel's inf-sup experiments better than
either repository's 1-D toy. `src/hertz_infsup_probe.py` evaluates that.

**Verdict: no, not as it stands** — its five parameters all enter through the
*right-hand side*, so `B` is parameter-independent, which is the wrong kind of
parametrization for a paper about parameter-dependent constraints. Across 40
configurations (curved contact surfaces, two-body displacement jumps, `N` swept
from 1 to `R−1`) `β^dec > 0` stays **provable** via a Gordan certificate. Its real
value is as a source of physically meaningful non-negative dual snapshots. Full
reasoning, including two probe defects found and fixed along the way, in
[REPRODUCTION_NOTES.md](REPRODUCTION_NOTES.md).

## Scope

The 2-D elastic contact application (§3, §6) — non-interpenetration on non-matching
meshes, collocation/LAC discretization, Hertz and ring-on-block test cases — is
**not** implemented, nor is the EIM separation of the nonlinear constraint (§4.3,
Algorithm 1 lines 2–3), which the paper deliberately leaves unspecified. The toy
problem exists only to exercise Algorithm 2. See REPRODUCTION_NOTES.md.
